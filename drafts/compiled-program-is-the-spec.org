* The load-bearing choice: deterministic, positional serialization
# The gotcha section — untie this knot with a concrete contrast.
# Positional (e.g. bincode-style) encoding writes fields/variants by ORDER, not by
# NAME. Consequences, stated as a rule:
#   - Renaming a field or a type: id UNCHANGED (names aren't in the wire form).
#   - Reordering struct fields or enum variants: id SILENTLY CHANGES.
#+begin_src rust
// Same bytes, different source names — identical hash:
enum Ref { Param(String), Evidence(String) }   // rename Param->Parameter: no change
// Reordering the variants below WOULD change every id (discriminant index shifts):
enum Ref2 { Evidence(String), Param(String) }  // <- different wire form!
#+end_src
# TODO: state the invariant the reader must respect: canonical form is defined by
# (order, types), never by names.

* Locking the wire format: a golden-hash test
# The concrete "how you don't get burned" payoff. Minimal test pinning one absolute
# digest so any future reorder fails loudly (relative-invariance tests won't catch
# an absolute drift).
#+begin_src rust
#[test]
fn spec_id_is_stable() {
    let p = compile("name pin\nparameters { max: int }\nrequires { evidence.x <= parameters.max; }");
    assert_eq!(hash(&p).to_base58(), "<PINNED_DIGEST>"); // regenerate once, then it guards forever
}
#+end_src
